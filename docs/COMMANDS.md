# Справочник команд

Общие флаги для всех команд: `--no-color` (отключить цвет, то же делает
переменная `NO_COLOR`) и `--ascii` (ASCII-рамки вместо Unicode-псевдографики).

```
procman <КОМАНДА> [ФЛАГИ]
```

Псевдонимы: `ps`, `ls` → `list`; `top`, `mon`, `live` → `watch`;
`pstree` → `tree`; `stop`, `taskkill` → `kill`; `sys`, `perf` → `summary`.

---

## `procman list` — список процессов

Псевдонимы: `ps`, `ls`.

```
procman list [--sort <КЛЮЧ>] [-n <N>] [-f <ТЕКСТ>] [-u <ИМЯ>] [--asc] [-c] [--json] [--no-header]
```

| Флаг | Описание |
|------|----------|
| `-s`, `--sort <КЛЮЧ>` | ключ сортировки: `cpu` (по умолчанию), `mem`, `pid`, `name`, `user`, `run`, `read`, `write` |
| `-n`, `--top <N>` | показать только N процессов |
| `-f`, `--filter <ТЕКСТ>` | фильтр по подстроке: имя, командная строка, PID, пользователь (без учёта регистра) |
| `-u`, `--user <ИМЯ>` | только процессы указанного пользователя |
| `--asc` | сортировать по возрастанию (по умолчанию числовые ключи — по убыванию, `pid`/`name`/`user` — по возрастанию) |
| `-c`, `--cmd` | добавить колонку с командной строкой |
| `--json` | вывод в JSON |
| `--no-header` | не печатать шапку со сводкой по системе |

Примеры:

```sh
procman list -n 15 --sort mem        # топ-15 по памяти
procman list -f chrome -c            # все процессы chrome с командными строками
procman list -s run --no-header      # без шапки, отсортировано по времени работы
procman list --json -n 5             # JSON для скриптов
```

Вывод содержит шапку (ОС, хост, ядра, аптайм), полоски общей загрузки CPU и
памяти и строку «суммарно по процессам».

## `procman watch` — живой монитор

Псевдонимы: `top`, `mon`, `live`.

```
procman watch [--interval <СЕК>] [--sort <КЛЮЧ>] [--asc] [-n <N>] [-f <ТЕКСТ>] [-u <ИМЯ>] [-c]
```

| Флаг | Описание |
|------|----------|
| `-i`, `--interval <СЕК>` | интервал обновления (по умолчанию 1.0, минимум 0.2) |
| `-s`, `--sort <КЛЮЧ>` | начальный ключ сортировки |
| `--asc` | начальное направление сортировки |
| `-n`, `--top <N>` | сколько процессов держать в списке (по умолчанию 500) |
| `-f`, `--filter <ТЕКСТ>` | начальный фильтр |
| `-u`, `--user <ИМЯ>` | только процессы пользователя |
| `-c`, `--cmd` | показывать командные строки |

Клавиши — в [README](../README.md#как-это-выглядит). Требуется интерактивный
терминал: при выводе в файл или пайп команда сообщает об этом и завершается с
кодом 1 (для пайпов используйте `list`).

## `procman info` — подробности о процессе

```
procman info <ЦЕЛЬ> [--json]
```

`ЦЕЛЬ` — PID (число) или имя процесса. Порядок поиска: PID → точное имя →
подстрока в имени → подстрока в командной строке/пользователе. Если совпадений
несколько, выбирается самый крупный по памяти, остальные перечисляются в stderr.

Что показывает: состояние, пользователя, родителя и цепочку процессов, число
дочерних и всех процессов в ветке, загрузку CPU (в процентах всех ядер и одного
ядра), резидентную и виртуальную память, время работы, время запуска (UTC),
чтение/запись диска, исполняемый файл, рабочий каталог и командную строку.

```sh
procman info 4321
procman info firefox --json
```

## `procman tree` — дерево процессов

Псевдоним: `pstree`.

```
procman tree [-r <ЦЕЛЬ>] [-f <ТЕКСТ>] [-u <ИМЯ>] [-s <КЛЮЧ>] [--depth <N>] [--json]
```

| Флаг | Описание |
|------|----------|
| `-r`, `--root <ЦЕЛЬ>` | показать только ветку этого процесса (PID или имя) |
| `-f`, `--filter <ТЕКСТ>` | оставить только ветки, где встречается подстрока |
| `-u`, `--user <ИМЯ>` | только процессы пользователя |
| `-s`, `--sort <КЛЮЧ>` | сортировка соседних узлов (по умолчанию по CPU) |
| `--depth <N>` | максимальная глубина (по умолчанию 12) |
| `--json` | вложенная структура в JSON |

В каждой строке: имя, PID, CPU, суммарная память ветки и число процессов в ней.
Корни — процессы, чей родитель отсутствует в выборке. Циклы в дереве
(встречаются в реальных системах) не приводят к зацикливанию — они помечаются.

```sh
procman tree --filter chrome
procman tree --root explorer
procman tree --depth 2 --root 1234 --json
```

## `procman kill` — завершение процессов

Псевдонимы: `stop`, `taskkill`.

```
procman kill <ЦЕЛЬ> [<ЦЕЛЬ> ...] [-y] [--dry-run] [-t] [--with-children] [--json]
```

| Флаг | Описание |
|------|----------|
| `-y`, `--yes` | не спрашивать подтверждение |
| `--dry-run` | только показать, что будет завершено |
| `-t`, `--terminate` | мягкое завершение (SIGTERM); если платформа его не поддерживает (Windows), применяется принудительное |
| `--with-children` | завершить и все дочерние процессы |
| `--json` | отчёт в JSON (требует `-y`) |

Поведение:

- цели ищутся по PID, затем по точному имени, затем по подстроке в имени, затем
  по командной строке/пользователю;
- перед завершением печатается список целей и запрашивается подтверждение (`y`/`да`);
- собственный процесс `procman` в план не попадает (с предупреждением);
- после завершения процессы перепроверяются: «завершён» или «завершается»;
- если что-то завершить не удалось (нужны права), команда завершается с кодом 1.

```sh
procman kill 4321                       # спросит подтверждение
procman kill notepad.exe -y              # все процессы с этим именем, без вопросов
procman kill 1234 --with-children --dry-run
procman kill explorer -t                 # мягкое завершение
```

## `procman summary` — производительность

Псевдонимы: `sys`, `perf`.

```
procman summary [--interval <СЕК>] [--fast] [-n <N>] [--json]
```

| Флаг | Описание |
|------|----------|
| `-i`, `--interval <СЕК>` | сколько наблюдать за сетью для расчёта скоростей (по умолчанию 1.0) |
| `--fast` | не ждать интервал (скорости сети будут нулевыми) |
| `-n`, `--top <N>` | сколько самых активных процессов показать (по умолчанию 5) |
| `--json` | вывод в JSON |

Разделы вывода: процессор (модель, максимальная частота, общая загрузка и
загрузка по каждому ядру), память и подкачка, диски (объём, занято, свободно,
процент), сеть (принято/отправлено всего, скорости приёма и передачи, пакеты),
самые активные процессы.

```sh
procman summary
procman summary --fast --top 10
procman summary --json | jq '.disks[] | {mount, used_percent}'
```

## Коды выхода

| Код | Когда |
|-----|-------|
| 0 | успех (в том числе пустой результат фильтра) |
| 1 | ошибка: процесс не найден, отказ в завершении, `watch` без терминала |
| 2 | ошибка разбора аргументов (обрабатывает clap) |
